# 資料作成（deck-builder）

「**資料作成して**」と言われたら、確認なしにこの手順を開始する。

## 0. 鉄則（全STEP共通）

1. **数値を創作しない。** 資料に載せる数字・固有名詞・出典は、案件フォルダの `01_データ/` のファイル・
   ブリーフ・Claude in Chrome で実際に読み取った画面のいずれかに実在するものだけ。
   無ければ「不足」として質問する。
2. **🔵観測 と 🟡推定 を分ける。** 実測値は🔵、こちらの解釈・試算・提言は🟡として、スライドの `note`（脚注）で明示する。
3. **構成案の合意なしに spec を書かない。** 先に構成案を出し、ユーザーの承認を得てから作り始める。
4. **`config/brand-rules.yaml` の禁止表現は資料にも適用する。** 問いかけ表現・カギ括弧・煽り表現を使わない。
5. **`engine/lib/` と `engine/build.mjs` は編集しない。** デザインシステムの共通部品。
   見た目を変えたいときは spec の `theme`（色）と分量調整で対応し、それで足りないときはユーザーに相談する。
6. **1スライド1メッセージ。** 見出しは説明ではなく結論を書く。

## STEP 1｜案件フォルダを用意する

1. `projects/` を一覧し、**対象の案件フォルダがあるか確認する**。
   - ユーザーが案件名を言っていれば、それに一致するフォルダを使う。
   - 複数あってどれか判断できないときは、一覧を見せて選んでもらう。
2. 無ければ、案件名を確認してから `projects/_TEMPLATE/` をコピーして `projects/<案件名>/` を作る。
   `<案件名>` は英数字とハイフン（例：`owned-media-proposal`）。
3. `projects/<案件名>/00_ブリーフ/deck-brief.md` を読む。
4. `config/brand-rules.yaml` を読む（トーン・禁止表現を資料にも適用するため）。

## STEP 2｜データを集める

**必ず `projects/<案件名>/01_データ/` を最初に一覧する。** 優先順位は次のとおり。

1. **`01_データ/` に置かれたファイル（最優先）**
   - そのまま読める：`.md` `.txt` `.csv` `.tsv` `.json` `.png` `.jpg`（スクショ）`.pdf`
   - `.xlsx` は直接読めないことがある。読めない場合は**CSVに書き出して置くようユーザーに依頼する**
     （勝手に変換スクリプトを書いて処理しない。数値の取り違えを防ぐため）
   - 読み取った数値は、**ファイル名と該当箇所を出典として控える**
2. ブリーフ（`00_ブリーフ/deck-brief.md`）に直接書かれた数値
3. ブリーフで指定されたURLを **Claude in Chrome** で開いて読み取る
   - 読み取る前に、**開いているページが対象のアカウント／プロジェクトかを確認する**。ページを移動するたびに確認する。
   - 読み取った内容は出典（ページ名・URL）と取得日時つきで控える。
4. どれも取れない場合は、**何が必要かを具体的に伝えて待つ**。推測で埋めない。

**ブリーフの ②ゴール と ④事実 の両方が空で、`01_データ/` も空の場合は、ここで質問する。**
ブリーフが未記入でも、`01_データ/` に元ネタがあれば進めてよい（ゴールと相手だけ対話で確認する）。
対話で聞き取った内容は、こちらで `00_ブリーフ/deck-brief.md` に記入して残す。

## STEP 3｜構成案を出して合意する

`templates/deck-prompt.md` の「STEP A：構成案の出力形式」に従って出力する。
出すのは①主張／②使う事実の一覧（🔵🟡と出典・取得日つき）／③不足情報／④スライド構成表／⑤含めないこと の5点。

**ユーザーの承認を得るまで次に進まない。** 修正指示があれば構成案を直して再提示する。

## STEP 4｜spec を書いてビルドする

1. `engine/specs/_TEMPLATE/spec.js` をコピーして `projects/<案件名>/02_ワーク/spec.js` を作る。
   - スキーマ：`engine/README.md`（14種のスライドと分量の目安）
   - 完成例：`engine/specs/sample/spec.js`
2. 合意した構成どおりに埋める。**★★（プレースホルダ）を残さない。**
3. 分量の目安（`engine/README.md`）を守る。CSSは自動縮小しないため、入れすぎると文字があふれる。
4. ビルドする：

   ```bash
   node engine/build.mjs "projects/<案件名>/02_ワーク/spec.js" "projects/<案件名>/03_納品/<案件名>_<YYYYMMDD>.html"
   ```

   `<YYYYMMDD>` は作成日。同じ日に作り直すときは同じファイル名に上書きしてよい。

5. **生成したHTMLを必ず目視確認する。** Claude in Chrome で生成したHTMLを開き、
   全ページを送って、文字あふれ・空欄・改行崩れ・誤字がないかを見る。
   問題があれば spec を直して再ビルドする（`lib/` は触らない）。

## STEP 5｜受け渡し

1. `templates/deck-prompt.md` の「出力前チェックリスト」を上から実行し、結果を報告する。
2. ユーザーに次を伝える：
   - 出力先：`projects/<案件名>/03_納品/<案件名>_<YYYYMMDD>.html`
   - **PDFにするには**：Chromeで開いて `Ctrl/Cmd + P` →「PDFに保存」（用紙と余白は設定済み。既定のままでよい）
   - 直したいときは「〇枚目の〇〇を直して」と言えば spec を直して再ビルドすること
3. 修正依頼は spec の該当スライドだけを直し、再ビルドして再確認する。

## よくある指示への対応

| 言われたこと | やること |
|---|---|
| 「資料作成して」 | STEP 1 から開始（案件フォルダの確認・作成） |
| 「〇〇の資料作成して」 | `projects/〇〇/` を探し、あればそれを使って STEP 1 から開始 |
| 「〇〇様向けの提案資料を作って」 | 宛名をブリーフ①に反映して STEP 1 から開始 |
| 「このフォルダのデータで作って」 | 指定フォルダを `01_データ/` として扱い STEP 2 から開始 |
| 「もっと短く」「10枚にして」 | 構成案の段階に戻し、章を削る（文字を詰めない） |
| 「色を変えて」 | spec の `theme` で上書き。`engine/lib/theme.css` は編集しない |
| 「PDFで」 | HTMLを生成し、Chromeでの「PDFに保存」手順を案内する |
| 「pptxで」 | 現在のエンジンはHTML/PDF出力のみと伝え、HTMLで出す。pptx化が必要ならユーザーに判断を仰ぐ |
