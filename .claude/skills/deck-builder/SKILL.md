# 資料作成（deck-builder）

「**資料作成して**」と言われたら、確認なしにこの手順を開始する。

## 0. 鉄則（全STEP共通）

1. **数値を創作しない。** 資料に載せる数字・固有名詞・出典は、`input/deck-brief.md`・参照ファイル・
   Claude in Chrome で実際に読み取った画面のいずれかに実在するものだけ。無ければ「不足」として質問する。
2. **🔵観測 と 🟡推定 を分ける。** 実測値は🔵、こちらの解釈・試算・提言は🟡として、スライドの `note`（脚注）で明示する。
3. **構成案の合意なしに spec を書かない。** 先に構成案を出し、ユーザーの承認を得てから作り始める。
4. **`config/brand-rules.yaml` の禁止表現は資料にも適用する。** 問いかけ表現・カギ括弧・煽り表現を使わない。
5. **`engine/lib/` と `engine/build.mjs` は編集しない。** デザインシステムの共通部品。
   見た目を変えたいときは spec の `theme`（色）と分量調整で対応し、それで足りないときはユーザーに相談する。
6. **1スライド1メッセージ。** 見出しは説明ではなく結論を書く。

## STEP 1｜ブリーフを読む

1. `input/deck-brief.md` を読む。
2. `config/brand-rules.yaml` を読む（トーン・禁止表現を資料にも適用するため）。
3. ブリーフで参照指定されたファイル・URLがあれば読む。
4. **①基本情報・②ゴール・③相手・④事実 のどれかが空なら、ここで質問する。**
   特に ② ゴール と ④ 事実 が空のまま進んではいけない。
   ブリーフが未記入の場合は、ファイルに書いてもらう代わりに**対話で聞き取って、こちらで `input/deck-brief.md` に記入してもよい**。

## STEP 2｜データを集める（必要な場合のみ）

優先順位は次のとおり。上から試す。

1. ブリーフに書かれた数値・このリポジトリ内のファイル
2. ブリーフで指定されたURLを **Claude in Chrome** で開いて読み取る
   - 読み取る前に、**開いているページが対象のアカウント／プロジェクトかを確認する**。ページを移動するたびに確認する。
   - 読み取った内容は出典（ページ名・URL）と取得日時つきで控え、構成案の事実一覧に反映する。
3. どちらも取れない場合は、**何が必要かを具体的に伝えて待つ**。推測で埋めない。

## STEP 3｜構成案を出して合意する

`templates/deck-prompt.md` の「STEP A：構成案の出力形式」に従って出力する。
出すのは①主張／②使う事実の一覧（🔵🟡と出典・取得日つき）／③不足情報／④スライド構成表／⑤含めないこと の5点。

**ユーザーの承認を得るまで次に進まない。** 修正指示があれば構成案を直して再提示する。

## STEP 4｜spec を書いてビルドする

1. `engine/specs/_TEMPLATE/spec.js` をコピーして `engine/specs/<資料名>/spec.js` を作る。
   - スキーマ：`engine/README.md`（14種のスライドと分量の目安）
   - 完成例：`engine/specs/sample/spec.js`
   - `<資料名>` は英数字とハイフンにする（例：`owned-media-proposal`）
2. 合意した構成どおりに埋める。**★★（プレースホルダ）を残さない。**
3. 分量の目安（`engine/README.md`）を守る。CSSは自動縮小しないため、入れすぎると文字があふれる。
4. ビルドする：

   ```bash
   node engine/build.mjs "engine/specs/<資料名>/spec.js" "output/<資料名>.html"
   ```

5. **生成したHTMLを必ず目視確認する。** Claude in Chrome で `output/<資料名>.html` を開き、
   全ページを送って、文字あふれ・空欄・改行崩れ・誤字がないかを見る。
   問題があれば spec を直して再ビルドする（`lib/` は触らない）。

## STEP 5｜受け渡し

1. `templates/deck-prompt.md` の「出力前チェックリスト」を上から実行し、結果を報告する。
2. ユーザーに次を伝える：
   - 出力先：`output/<資料名>.html`
   - **PDFにするには**：Chromeで開いて `Ctrl/Cmd + P` →「PDFに保存」（用紙と余白は設定済み。既定のままでよい）
   - 直したいときは「〇枚目の〇〇を直して」と言えば spec を直して再ビルドすること
3. 修正依頼は spec の該当スライドだけを直し、再ビルドして再確認する。

## よくある指示への対応

| 言われたこと | やること |
|---|---|
| 「資料作成して」 | STEP 1 から開始 |
| 「〇〇様向けの提案資料を作って」 | 宛名をブリーフ①に反映して STEP 1 から開始 |
| 「もっと短く」「10枚にして」 | 構成案の段階に戻し、章を削る（文字を詰めない） |
| 「色を変えて」 | spec の `theme` で上書き。`engine/lib/theme.css` は編集しない |
| 「PDFで」 | HTMLを生成し、Chromeでの「PDFに保存」手順を案内する |
| 「pptxで」 | 現在のエンジンはHTML/PDF出力のみと伝え、HTMLで出す。pptx化が必要ならユーザーに判断を仰ぐ |
