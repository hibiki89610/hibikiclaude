# LLMO無料分析レポート作成

Emma LLMOツールの実測データを、クライアント向け無料診断レポート（pptx・約28枚）に変換するスキル。
利用者は非エンジニアの営業・CSメンバーであることが多い。**対話は日本語・専門用語は噛み砕いて・確認はこまめに。**

## 0. 前提・鉄則（品質と信頼性の生命線）

このレポートは実在の取引先に見せる「診断」であり、数値の誤りや誇張はクライアントの意思決定を誤らせ、
景表法などの法的リスクにもなる。だからこそ以下は絶対に譲らない：

- **数値（KPI・順位・掲載状況・スコア）はツールの実測のみ**。無い数値を創作しない。ツール画面で確認していない数字・媒体名・記事名を書かない。
- **ヒアリングの差分・所見・提案の方向性は「推定・提言」**として、実測値とはっきり分けてラベル表示する（レポート内では 🔵観測 / 🟡推定）。
- **無料版のスコープを守る**：計測プロンプトは限定本数と明記。サイテーションのメディアリストはサンプル3〜4件のみ（全リストは有償）。対策は方向性のみを4つまで（タスク分解・実行手順は書かない＝コンサル領域）。
  詳細：[references/stance-and-scope.md](references/stance-and-scope.md)
- **計測データが無ければ、レポートは作らない**（推定で数値の穴を埋めることは絶対にしない）。停止条件はSTEP 1.5を参照。

## STEP 0｜添付ファイル・過去データの確認（質問する前に必ず先にやる）

**このステップを飛ばしていきなりユーザーに質問しない。** 会話やこのメッセージに、キット一式やクライアントの作業フォルダを含む
ファイル（zipなど）が添付・共有されている場合は、まずその中身を自分で確認する：

1. 添付ファイルがあれば展開・閲覧し、`03_クライアントレポート/<クライアント名>/`（またはそれに類するクライアント別フォルダ）の中に、
   今回頼まれたクライアントのフォルダが無いか探す。
2. 見つかったら、`00_ヒアリング/`のヒアリングシート、`01_データ/`のスクショ・テキスト、`02_ワーク/`の取得メモや過去のspecファイルを
   自分で読み込む。**これらが揃っていれば、STEP 1・STEP 2で同じ内容をユーザーに聞き直さない。**
3. 一部だけ見つかった場合（例：ヒアリングシートはあるが計測データのメモが古い）は、**足りない部分だけ**をSTEP 1以降で確認する。
4. 何も添付されていない、またはそのクライアントのフォルダが無い場合は、通常どおりSTEP 1から進める（新規クライアントの初回はヒアリングから
   一つずつ確認することになる。これは省略できない仕様）。

ユーザーによっては「毎回キット一式のzipを渡してから頼む」運用をしている。その場合はこのSTEP 0だけで大半の情報が揃うはずなので、
「資料作成して」の後に来る質問はぐっと減る。逆に、hearingシートも無い本当に初めてのクライアントであれば、
ブランド定義など人でないと埋められない項目は今後もその都度質問することになる（数値を創作しないルールを優先するため）。

## 作業ディレクトリについて

このスキルは特定のフォルダ構成に依存しない。STEP 0で見つけたクライアントフォルダがあれば、以後の成果物もその中の対応する場所
（`02_ワーク/`・`03_納品/`など）に保存してよい。無ければ、成果物（ヒアリングシート・取得データメモ・spec・pptx・サマリー）を
どこに保存するか、ユーザーに一度だけ確認する（例：ローカルの `LLMO案件/<クライアント名>/` フォルダ、共有ドライブの案件フォルダなど）。

## STEP 1｜クライアントと対象サイトの確認（必須・省略不可）

1. **クライアント名と対象サイト**をユーザーに確認する。すでにメッセージに含まれていれば（例：「〇〇様の資料作成して」）、それを使って構わない。
   ただし複数サイトを持つクライアントの可能性がある場合は、対象サイトも確認する。
2. ヒアリングシート（ブランド定義＝「AIに何者として覚えてもらいたいか」を含む）があるか確認する。STEP 0で見つかっていればそれを使う。
   無ければ [templates/summary-template.md](templates/summary-template.md) に必要な項目が示されているので、対話で埋める。
   ブランド定義が無いとブランド差分分析ができないため、無ければユーザー経由でクライアントに確認してもらう。
3. Claude in Chromeでツールを開く場合、**左上ヘッダのクライアント／サイトのプルダウンを読み取り、対象と一致しているか必ず確認する**。
   - 一致していなければ切り替え、**切り替え後にもう一度読み取って一致を確認**してから先に進む（別クライアントのデータが残っていることがある）。
   - **この確認が取れるまで、いかなるデータも読み取らない・記録しない。**
   - ページを遷移するたびに、ヘッダのクライアント名を再確認する（データの取り違え防止）。

## STEP 1.5｜計測データの存在チェック（無ければここで停止）

レポートに使う計測データは、このセッションより前にツール内で計測を実行しておく運用になっている（このスキルの中で計測は実行しない）。
`/monitoring` を開き、以下をチェックする：

- 「最終取得」日時が存在するか
- ジャーニー4KPI（引用率／言及率／勝率／ポジ率）に数値が入っているか
- プロンプト一覧が「未計測」ばかりでないか

**1つでも満たさない場合は、ここで作業を停止する。** spec作成・pptx生成に進んではいけない。ユーザーには次のように案内して終了する：

> 「このクライアントはまだ計測データがありません。ツールの `/monitoring` で『計測を実行』し、完了後（通常しばらく時間がかかります）に改めて依頼してください。ツールへの登録がまだの場合は、先に登録作業（クライアント登録・プロンプト設定）が必要です。」

最終取得日が**30日以上前**の場合は停止しないが、「データが古い（<日付>取得）。再計測してから作ることを推奨」とユーザーに確認を取ってから進める。

## STEP 2｜データ取得（4分析ページ）

取得方法は3経路。**上から順に試す**：

- **A. Claude in Chrome（第一選択）**：ツールの各ページを開いて読み取る。1タブを使い回し、終了時に閉じる。
- **B. ユーザーが貼り付けたスクショ／テキスト**：会話にスクリーンショットが貼られている、またはユーザーがすでにテキストを貼り付けている場合はそちらを優先して読む。テキストで正確に取りたい場合は [templates/gemini-extraction-prompt.md](templates/gemini-extraction-prompt.md) のプロンプトをユーザーに案内してもよい。
- **C. Dify等の生データ（CSV）**：ユーザーが計測の生データCSV（プロンプト×エンジン×ブランドの登場○×表、Shift-JIS/UTF-8どちらも可）を持っている・添付している場合、
  `node scripts/engine/parse_csv.js "<CSVが入っているフォルダ>"` でブランド別の登場率（合計・エンジン別）を集計できる。出た数値をそのまま🔵観測として使う（Claudeが新たにAIへ聞き直す必要はない）。
- どれも無理なら、必要なページ（`/monitoring`・`/brand-listening`・`/citation-list`・`/site-audit`）と取得手順をユーザーに具体的に案内して待つ。

取得する4ページと読み取り項目（詳しい読み方は各参照ファイル）：

| ページ | 読み取ること | 参照 |
|---|---|---|
| `/monitoring` | ジャーニー4段階のKPI（情報収集=引用率／ブランド想起=言及率・平均順位／比較検討=勝率／意思決定=ポジ率）、強い・弱いプロンプト群、計測日 | [references/funnel-kpi.md](references/funnel-kpi.md) |
| `/brand-listening` | ポジション方針の達成状況（意図どおり/要対策）、自社が勝者の認識軸、競合支配・圏外の認識軸 | [references/brand-gap-analysis.md](references/brand-gap-analysis.md) |
| `/citation-list` | 掲載数/全媒体数、平均掲載順位、掲載依頼候補数、Impact Score上位の未掲載メディア3〜4件（媒体名・記事名・AI引用回数・競合掲載状況） | [references/citation-analysis.md](references/citation-analysis.md) |
| `/site-audit` | 平均スコア、診断ページ数、S/A/B/C分布、低スコアページの傾向 | [references/site-audit-summary.md](references/site-audit-summary.md) |

取得した生データは、**ページごとに個別の取得日時つきで**メモしておく（後から検証できるように。作業ディレクトリのメモファイルなどに残す）。
4ページを別の日にまたがって取得した場合、日付を1つに丸めない。

**貼り付けデータが集計値のみで、個票（実際の計測プロンプト文言・記事タイトルなど）が無い場合の扱い**：
無いものを創作しないという鉄則を優先する。
- `scope`（計測プロンプト表）を埋める実際のプロンプト文言が無い場合は、ジャーニー段階ごとの代表的な質問カテゴリの記述に留め、脚注で「プロンプト文言は今回未確認」等と明記する。
- サイテーションのサンプル行で記事タイトルが分からない場合は、タイトル欄に「記事名は今回未取得」のように書き、架空のタイトルを作らない。
- サイテーションのサンプル件数は3〜4件が目安だが、提供されたデータがそれより少ない場合は件数を水増ししない（少ない件数のまま使ってよい）。

## STEP 3｜分析（ここから「推定・提言」）

1. **ファネル分析**：4KPIのどこで落ちているか、原因仮説（プロンプト群の傾向から）
2. **ブランド差分分析**：ヒアリングの「ありたい認識」×ツールの「現状認識」→ 強めるべき軸・作るべき軸・抑えるべき軸
3. **サイテーションギャップ**：掲載可能性の総数を示し、象徴的なサンプル（競合掲載あり×自社なし／自社が下位掲載）を3〜4件選ぶ
4. **サイト要因**：スコア分布とファネル弱点の関係（例：意思決定が弱い×信頼系ページが低スコア）
5. **FACT3つ**：強み1・課題1・機会1 を実測値つきで
6. **対策の方向性4つ**：実測に紐づけて。**タスク分解しない**

分析結果を対話でユーザーに提示し、フィードバックを反映してから次へ進む。

## STEP 4｜spec作成 → pptxビルド

pptx生成にはNode.jsスクリプト（このスキル同梱の `scripts/engine/`）を使う。`pptxgenjs` は実行環境に入っている想定なので
`npm install` は不要（`require("pptxgenjs")` が失敗した場合のみ、**`scripts/engine/` ディレクトリの中で** `npm install pptxgenjs` を試す。
作業ディレクトリやカレントディレクトリで実行するとNode.jsのモジュール解決に失敗することがあるため、必ず `build.js` と同じ階層で行う）。

1. `scripts/engine/specs/_template/spec.js` を作業ディレクトリにコピーし、STEP 2/3の内容で埋める。
   - スキーマの説明：[scripts/engine/specs/README.md](scripts/engine/specs/README.md)
   - 埋め方の完成例：[scripts/engine/specs/sample/spec.js](scripts/engine/specs/sample/spec.js)（自社データのサンプル）
2. ビルドを実行する（spec・出力先とも絶対パスを渡すこと。`build.js` はカレントディレクトリに依存する相対パス解決をするため）：
   ```
   node <このスキルのパス>/scripts/engine/build.js "<作業ディレクトリ>/spec.js" "<出力先>/<クライアント名>_LLMO無料分析_<YYYYMMDD>.pptx"
   ```
3. 生成したpptxをユーザーに渡して確認してもらう。修正はspecを直して再ビルドする。

## STEP 5｜サマリーと引き継ぎ

- [templates/summary-template.md](templates/summary-template.md) の体裁でサマリーMarkdownを作成する（観測🔵/推定🟡ラベル付き）。
- 出力前チェックリスト：
  - [ ] 数値はすべてツール実測。創作なし・計測日明記
  - [ ] 🔵/🟡がスライド脚注で分離されている
  - [ ] メディアリストはサンプルのみ（全リストを載せていない）
  - [ ] 対策は方向性のみ（タスク・手順を書いていない）
  - [ ] ご支援メニュー（コンサル月60万円〜／ツール契約／レポーティング＋助言 月1回）とブランド定義見直し支援が入っている（`services`/`pricing` を specで上書きしていない限り、エンジンが自動で入れる）
  - [ ] 料金2枚（対応範囲・サンプル料金）の数字が最新の確定条件と一致しているか（[references/pricing-and-scope.md](references/pricing-and-scope.md) に「要確認」と明記された項目がある。**クライアントに出す前に必ず最新条件を社内で確認するようユーザーに伝える**）
  - [ ] pptxとサマリーMarkdownをユーザーに渡した

ユーザーから「有償のコンサルでは具体的に何をするのか」と聞かれた場合は、
[references/paid-tier/README.md](references/paid-tier/README.md) の手法（KBF分析・AI Voice・Company Voiceのサイト実クロールなど）を参考に説明してよい。
**ただし無料版レポート自体の作成にこれらの手法は使わない**（無料版スコープを超えるため）。
