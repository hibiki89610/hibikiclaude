# Company Voice・自社サイトクロール分析（自社が「何者」と発信しているか）

SKILL STEP6 の詳細。**対象サイトを実際にクロールし、(1)保有する強み資産の抽出／(2)AIに読まれやすい構造かの技術診断／(3)所見（評価点・課題）**を出すモジュール。PDF「3つの声＝Company Voice」／実クライアントデッキ「公式サイトの現状所見」「保有している強み資産」に対応。

---

## 1. クロールの実行（🔵観測）

対象URLと主要下層（TOP／商品／会社概要／FAQ／実績・事例／比較・選び方）を `WebFetch` またはブラウザで実際に取得する。取得できたページのみを観測対象とする（未取得は⚪要確認）。

記録：ページURL／取得日／本文テキスト／構造化データ有無／画像依存度。

---

## 2. 強み資産の抽出（🔵観測）

サイトに**実際に書かれている**独自実績・数値・技術・認証・素材・スピードを、**原文のまま**抜き出す（創作しない）。

出力＝**強み資産カード群**（実クライアント例）：

| カテゴリ | 値 | 出典（サイト内） |
|---|---|---|
| 実績 | Web通販20周年 | /about |
| 実績 | 顧客満足度98%、印刷実績No.1（表記） | TOP |
| 品質 | 完全国内自社製造、超音波溶着の独自技術 | /quality |
| 品質 | 7種類の素材ラインナップ | /product |
| 環境 | SBT認定・FSC認証・LIMEX対応 | /sustainability |
| スピード | 最短2営業日発送 | TOP |
| 拡張性 | 姉妹サイト（ドージンファクトリー等） | footer |
| 露出 | P・Iショー出展、業界紙掲載 | /news |

> これらは「テキスト化されて第三者から見える場所に置かれた時」に最大効果を発揮する（＝RTBの原資）。

---

## 3. 技術診断（🔵観測・約30項目）

AIが情報を読み取り信頼しやすい構造かを実測で判定（◎/○/△/×）。

- **構造化データ**：Organization / sameAs / Service・Product / BreadcrumbList / FAQPage / Article / Dataset / VideoObject。**全ページにPerson・Organization**が入っているか。
- **クローラビリティ**：robots.txtでGPTBot等を許可しているか／サイトマップ／JS依存度／PDFのテキスト化。
- **LLM可読性**：見出し構造(H1-H6)の論理性／要約セクションの有無／**画像依存度（商品情報が画像中心でテキストが薄くないか）**／Code-to-Text比率。
- **E-E-A-T**：著者・運営者情報の構造化／更新日・一次情報への発リンク。
- **エンティティ**：ブランド/製品名の表記統一。

---

## 4. 所見の生成（🟡推定）

観測（§2・§3）を「評価できる点」と「AIに引用されにくい要因（課題）」に整理する。

**評価できる点（例）**：商品ラインナップが豊富／独自実績が明確／サステナ訴求材料が豊富／姉妹サイト連携。

**AIに引用されにくい要因＝課題（例）**：
- 「比較表」「選び方ガイド」などAIが好むテキスト中心の解説コンテンツが少ない
- 商品情報が画像中心でAIが読み取りにくい
- 「他社と比べて何が優れているか」を文章で示すコンテンツが無い
- FAQの構造化（FAQスキーマ）が不十分
- メディア掲載・第三者評価をまとめた「お墨付き」ページが目立たない

要点：**「商品を売る作り」は優秀だが「AIに読ませる作り」が手薄**、という型で締める（🟡【推定】＋根拠に🔵観測項目を併記）。
→ デッキ「公式サイトの現状所見」「保有している強み資産」スライド。

---

## 5. 3つの声の突き合わせ（Company × User × AI）

PDFの核。3声のズレを可視化する（Userは無料分析では簡易、本提案ではインタビュー/レビューで補強）。

| 声 | 取得元 | 内容 |
|---|---|---|
| Company Voice | 本モジュール（クロール） | 自社が発信している「何者か」 |
| User Voice | レビュー/成約者/アンケート（本提案）※無料分析では代替でレビュー観測 | 顧客が語る「選定理由・価値」 |
| AI Voice | AIVoice_エンティティ.md | AIが説明する「何者か」 |

ズレがあれば「どの定義を正とするか」を戦略（STEP7）で提言（🟡）。将来像と違えば経営判断で新定義を定め発信で浸透させる。
