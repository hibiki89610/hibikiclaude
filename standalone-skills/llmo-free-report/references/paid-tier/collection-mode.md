# 収集モードの自動判定と実行（Dモード / Bモード）

SKILL STEP1 の詳細。**「Difyで生データを出して渡すケース」と「無い場合はClaudeがブラウザで実観測し引用元URLを実在確認するケース」の両方を自動で扱う**ための手順。

---

## 1. 判定ロジック

```
入力にAI回答の生データ（CSV/表/貼付テキストで、各エンジンの回答本文 or 参照URLを含む）があるか？
├─ ある  → Dモード（渡された生データを整形・評価する。AIに聞き直さない）
└─ ない  → Bモード（ブラウザで各AIに実際に聞いて観測する）
```

判定はClaudeが自動で行う。曖昧な場合（一部だけ生データがある等）は、**ある分はDモード扱い・足りない分はBモードで補完**し、どちらで取得したかを行ごとに明記する。

---

## 2. Dモード（Dify等の生データあり）

前提：`LLMO調査ベータ（Dify経由で3エンジン取得）` などで、プロンプト×エンジン×アカウント×期間の回答が既に取得されている。

手順：
1. 生データを表に正規化（列：プロンプト／エンジン／アカウント／取得日／回答本文／参照URL）。
2. **言及判定**：各回答に自社・競合が「推奨(○◎)／言及のみ(△)／なし(×)」で出るかを機械的に付与。
3. **登場率**：分母＝(エンジン数 × アカウント数 × 期間)。分子＝○＋△の回数。プロンプト別・対象別に集計。
4. **引用URL抽出**：回答内の参照URLをすべて抜き、`https://` から省略せず記載。**§4の実在確認**を通したものだけ事実欄に採用。
5. 出典に「Dify取得・取得回数・期間・パーソナライズ条件」を明記。

Dモードでは**Claudeは新たにAIへ問い合わせない**（データの一貫性を保つため）。不足があればユーザーに追加取得を依頼するか、Bモードで補い、補った旨を明記。

---

## 3. Bモード（生データなし → Claudeがブラウザで実観測）

前提：ヒアリング情報のみ。Claudeが `mcp__Claude_Browser__`（アプリ内ブラウザ。ログイン不要な公開UIを想定）または `mcp__claude-in-chrome__`（ログイン済み実Chrome）で実際にAIに聞く。

手順：
1. **観測可否を確認**：ブラウザツールが使える環境か。使えない（ヘッドレス/権限なし）なら**観測不能を宣言し、登場率・引用URLは空欄**（推測で埋めない）。
2. **測定プロトコル**（再現性優先）：
   - パーソナライズ/履歴の影響を避ける（新規セッション・ログイン最小化）。
   - **重点プロンプトは同一条件で複数回**（目安3〜10回。無料分析は負荷を見て3回程度でもブレ幅は必ず記録）。
   - 対象：ChatGPT / Gemini / Claude ＋（可能なら）Perplexity。**Google AI Overviews** は検索で該当クエリを引き、表出有無・表示位置（メイン枠/右サイド）を手動確認。
   - 強制ランキング指示（「1位/2位/3位で」）を付け、推奨順位を取得。
3. **記録**：エンジン／取得日時／試行回／回答本文（要点）／自社・競合の言及記号／参照URL。
4. **引用URLの実在確認**（§4）を必ず実施。
5. 出典に「Claude実観測・取得日・試行回数・対象エンジン・パーソナライズ条件」を明記。

### 非決定性の明示
AI回答は毎回揺れる。**単発の結果を断定に使わない**。「3回中2回で登場（登場率目安）」のように試行数とともに示す。

---

## 4. 引用元URLの実在確認（両モード共通・必須）

1. 抽出した各URLを `WebFetch` または ブラウザで**実際に開く**。
2. 到達可否・タイトル・当該内容の有無を確認：
   - 到達し内容が一致 → **事実欄に採用**（★実在確認済）。
   - 到達するが内容が違う/リダイレクト → 注記して採用可否を判断。
   - 到達しない（404/存在しない） → **事実欄から除外**し「AIが提示したが未確認/実在せず」と別記。
3. **AIが幻覚でURLを出すことがある**前提で扱う。確認できないURLを顧客提示物に載せない。

---

## 5. 出力への反映

- 登場率・引用URLの表には、行または表脚注に**「取得モード（D/B）・条件・取得日」**を必ず添える。
- 「全プロンプト×毎週×全エンジンを観測したかのように見せない」。**実際に観測した範囲だけ**を観測系として示し、残りは生成系（推定）に落とす。
