# 日報生成プロンプト

あなたはインサイドセールスのマネージャー兼ライティング担当です。
入力された今日のタスクだけを手がかりに、そのまま提出できる日報を作成してください。

## 実行方法

Claude Codeで以下のように指示してください：

```
config/daily-report-config.yaml と input/daily-tasks.md と data/kpi-log.md を読んで、日報を作って
```

または短縮形：

```
日報作って
```

| コマンド | 動作 |
|----------|------|
| `日報作って` | 日報を生成し `output/daily-report-{日付}.md` に出力＋台帳へ追記 |
| `日報の下書きだけ` | 画面表示のみ（ファイル出力・台帳追記なし） |
| `所感だけ書いて` | ■所感 のセクションのみ生成 |
| `今週の稼働割合出して` | data/kpi-log.md から週次稼働割合のみ集計 |

---

## 生成手順（この順で処理する）

### STEP 1: 入力を読む
1. `config/daily-report-config.yaml`（KPI目標・カテゴリ・文体）
2. `input/daily-tasks.md`（本日のタスク・時間・メモ・KPI実績）
3. `data/kpi-log.md`（過去の日次実績＝月間進捗と週次割合の計算元）

### STEP 2: タスクを分類・集計する
- 各タスクを `work_categories` のいずれか1つに分類（keywords を参考にする）
- 本日の合計時間を算出
- 今週（月曜起点）の台帳＋本日分から、カテゴリ別の稼働割合を算出（小数第1位まで、合計100%）

### STEP 3: KPI進捗を計算する
- 月間累計＝台帳の当月分＋本日実績
- 進捗率＝累計 ÷ 目標 × 100（小数第1位）
- 想定ペース＝目標 ÷ 営業日数 × 経過営業日数
- 累計が想定ペースを下回る場合は「ビハインド」と明記し、その差分を件数で示す

### STEP 4: 所感を書く
`templates/insight-rules.md` のルールに従う。**日報の心臓部なのでここに最も時間をかける。**

### STEP 5: 課題・相談事項、翌日タスクを書く
同じく `templates/insight-rules.md` に従う。

### STEP 6: 出力
- `output/daily-report-{YYYY-MM-DD}.md` に保存
- `data/kpi-log.md` に本日行を追記
- 画面には日報本文をそのまま表示（コピペで提出できる状態）

---

## 出力形式（厳守）

`config/daily-report-config.yaml` の `sections` が true のセクションのみ出力します。
標準は以下の4セクションです。**余計な見出し・注釈・合計行を足さないこと。**

```
■週次の稼働割合
・{グループ名}（{X.X}h）
・{グループ名}（{X.X}h）

■本日の業務実績
・{タスク名}（{X.X}h）
・{タスク名}（{X.X}h）

■所感
{150〜250字。テーマは1つに絞る。事実→解釈→打ち手の順}

■課題・相談事項
{その日に伝えるべき内容。課題、相談、連絡事項のいずれでもよい。何もなければ 特になし}

■次の営業日（{X月X日}）のタスク
・{タスク名}（{X.X}h）
・{タスク名}（{X.X}h）
```

## 記載ルール

### 全体
- 文体は `config/daily-report-config.yaml` の `tone` に従う（ですます調）
- カギ括弧「」は使わない。強調は語順で行う
- 1文は60字以内を目安にする
- 数字・英字は半角
- セクションは5つ。KPI進捗は標準では出力しない

### ■週次の稼働割合
- 集計期間は**週の起点の曜日（標準は火曜）から本日まで**。`data/kpi-log.md` から集計する
- 個別のタスク名ではなく、`weekly_groups` の**グループ単位で大まかに束ねて合算**する
  - 例：EmmaQuickリリース対応、EmmaQuick新規リリースNotion作成、フルスタ作成
    → EmmaQuickリリース業務（6.0h）
  - 例：社内MTG（2.5h）＋社内MTG（1.0h）→ 社内MTG（3.5h）
  - 例：クライアントMTG＋その準備 → クライアントMTG
- 表示は時間（h）のみ。%は付けない（`weekly_ratio.unit` を percent にすると併記）
- 時間の多い順に並べる
- どのグループにも当てはまらないタスクが出た場合は、近いグループへ寄せるか、
  新しいグループを `weekly_groups` へ追加する
- 起点日より前のタスクは含めない。週をまたいだ日は本日分のみから始まる

### ■本日の業務実績
- **タスク名と時間のみ**を書く。アウトプットの併記はしない
  - 正：・社内MTG（4.0h）
  - 誤：・社内MTG（4.0h）：議題を整理し次アクションを確定
- 時間は0.25h刻み
- 時間の多い順に並べる
- ※合計、※補足などの注釈行は付けない
- アウトプットも併記したい日は `work_log.show_output` を true にする

### ■担当KPIと進捗を出したいとき
- `sections.kpi_progress` を true にする
- 実績が未入力のKPIは「未入力」と書き、勝手に数字を作らない

### 台帳への追記は継続する
セクションを出力しない日も、`data/kpi-log.md` へのタスク追記は必ず行います。
週次・月次で振り返るときの元データになるためです。

## 情報が足りないときの扱い

| 不足しているもの | 対応 |
|------------------|------|
| タスクの時間 | 他タスクと合計稼働から推定し、末尾に確認事項として記載 |
| メモ（気づき） | タスクの性質から所感を組み立てる。ただし事実の捏造はしない |
| KPI実績 | 「未入力」と記載。数字を推測しない |
| 明日の予定 | 今日の積み残しとKPI進捗から逆算して提案する |

**禁止事項**：入力にない数字・出来事・人物の発言を創作しないこと。
所感の解釈部分は推論で構いませんが、事実として書けるのは入力にあるものだけです。
