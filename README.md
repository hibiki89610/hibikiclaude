# 記事レビュー＆資料作成キット

Claude（Claude Code / Claude in Chrome）を使った半自動の記事レビュー＆自動修正システムです。
**ファクトチェック機能**と、**16:9スライド資料の作成機能**も搭載しています。

## ディレクトリ構成

```
hibikiclaude/
├── CLAUDE.md                   # Claudeへの指示（どの合言葉で何をするか）
├── .claude/skills/
│   └── deck-builder/SKILL.md   # 資料作成の手順書（Claudeが読む）
├── config/
│   └── brand-rules.yaml        # ブランドルール設定（一度設定すればOK）
├── input/
│   └── article.md              # 記事入力用（都度編集）
├── projects/                   # 資料の案件フォルダ
│   ├── _TEMPLATE/              # コピー元（ブリーフ・データ・ワーク・納品）
│   └── <案件名>/               # 案件ごと。元ネタは 01_データ/ に置く
├── output/
│   ├── article-fixed.html      # 修正済みコード出力先
│   └── sample-deck.html        # 資料の完成サンプル（15枚）
├── templates/
│   ├── review-prompt.md        # レビュー出力形式の定義
│   ├── auto-fix-rules.md       # 自動修正ルール
│   ├── fact-check-prompt.md    # ファクトチェック出力形式
│   ├── fact-check-fix-rules.md # ファクトチェック修正ルール
│   └── deck-prompt.md          # 資料の構成案フォーマットとチェックリスト
├── engine/                     # 資料作成エンジン
│   ├── build.mjs               # spec → HTML のビルド
│   ├── README.md               # spec のスキーマ（スライド14種）
│   ├── lib/                    # デザインシステム（編集しない）
│   └── specs/
│       ├── _TEMPLATE/spec.js   # 新規資料のひな形
│       └── sample/spec.js      # 完成例
└── README.md
```

## 機能一覧

| コマンド | 機能 |
|----------|------|
| `レビューして` | トンマナ/SEOチェック＆修正案提示 |
| `レビューして修正まで` | レビュー＋自動修正＋HTML出力 |
| `修正だけして` | レビュー省略で修正済みHTML出力 |
| `ファクトチェックして` | 要検証主張の抽出＆チェック計画作成 |
| `ファクトチェックして修正まで` | ファクトチェック＋自動修正＋HTML出力 |
| `資料作成して` | ブリーフから構成案を作成＆16:9スライド資料（HTML/PDF）を生成 |

## 使い方

### STEP 1: ブランドルールを設定（初回のみ）

`config/brand-rules.yaml` を開き、以下を設定：

- 口調（ですます/だである）
- トーン（丁寧/カジュアルなど）
- 禁止表現・禁止ワード
- 文字作法（半角全角ルール）
- SEO要件

### STEP 2: 記事と情報を入力（都度）

`input/article.md` を開き、以下を入力：

1. **記事情報**（表形式）
   - 目的
   - ターゲットKW
   - 二次KW
   - 競合差分

2. **記事本文**
   - コードブロック内に貼り付け

### STEP 3: レビュー＆修正を実行

#### レビューのみ
```
レビューして
```

#### レビュー＋自動修正＋HTML出力（推奨）
```
レビューして修正まで
```

### STEP 4: 結果を受け取る

**レビュー結果**:
1. 総評（200字以内）
2. トンマナ逸脱リスト（表形式）
3. 読みやすさ改善（箇条書き）
4. SEO改善（箇条書き）
5. 重要度タグ（A/B/C）
6. 修正後サンプル文章（3箇所）

**修正済みHTML**:
- `output/article-fixed.html` に出力
- 修正ログも併せて表示

## 自動修正の対象

### 重要度A（必須修正）- 自動対応
| 項目 | 内容 |
|------|------|
| カギ括弧削除 | 「」を全て削除 |
| 問いかけ修正 | 〜ませんか？→平叙文に変換 |
| HTML構文修正 | 閉じタグ漏れ等を修正 |

### 重要度B（推奨）- 自動対応
| 項目 | 内容 |
|------|------|
| 長文分割 | 80字超の文を分割検討 |
| 表記統一 | brand-rules.yaml に従い統一 |

### 手動対応が必要
- SEO関連（タイトル、KW配置）
- コンテンツの追加・削除
- 画像alt属性の設定

## カスタマイズ

### 禁止ワードを追加する

`config/brand-rules.yaml` の `prohibited.words` に追加：

```yaml
prohibited:
  words:
    - "絶対"
    - "必ず"
    - "誰でも簡単に"
```

### 用語統一を設定する

`config/brand-rules.yaml` の `writing_rules.terms` に追加：

```yaml
writing_rules:
  terms:
    SEO: "seo, Seo"
    Webサイト: "WEBサイト, webサイト"
```

## ファクトチェック機能

### 概要

記事内の「検証が必要な主張」を自動抽出し、チェック計画を作成します。
数値、統計、法律、医療など、誤りがあると信頼性を損なう情報を重点的にチェックします。

### 使い方

#### STEP 1: 記事を入力
`input/article.md` に記事本文を貼り付け

#### STEP 2: ファクトチェック実行
```
ファクトチェックして
```

#### STEP 3: 結果を確認

**出力内容**:
1. リスク評価の総評（100〜200字）
2. 要検証リスト（表形式）
3. 断定回避テンプレ（5つ）
4. 最優先確認リスト（上位5件）

#### STEP 4: 修正まで実行（オプション）
```
ファクトチェックして修正まで
```

### ファクトチェック出力サンプル

```
## 1) リスク評価の総評
本記事には12件の検証が必要な主張が含まれています。
特に数値データ（5件）と法律関連（2件）はリスクが高く、
公式出典での確認が必須です。医療効果に関する記述は
表現の緩和を推奨します。

## 2) 要検証リスト
| # | 主張 | 種類 | リスク | 理由 | 検証方針 | 推奨出典 | 修正案 |
|---|------|------|--------|------|---------|---------|--------|
| 1 | 利用者数は1億人を突破 | 数値 | 高 | 出典不明 | 公式発表を確認 | 企業IR/プレスリリース | 約1億人以上とされています |
| 2 | 業界シェア1位 | 統計 | 高 | 比較時点不明 | 調査会社データを確認 | 矢野経済研究所等 | 主要なサービスの一つ |

## 3) 断定回避テンプレ
- 〜とされています
- 〜と言われています
- 〜という報告があります
- 一般的に〜と考えられています
- 〜の傾向が見られます

## 4) 最優先確認リスト
1. 利用者数は1億人を突破（数値/高）- 法的リスク回避のため
2. 業界シェア1位（統計/高）- 景表法違反リスク
3. ...
```

### チェック対象の種類

| 種類 | 説明 | リスク基準 |
|------|------|-----------|
| 数値 | 具体的な数字、金額、% | 出典不明なら高 |
| 統計 | 調査結果、ランキング | 時点・母数不明なら高 |
| 法律 | 法令、規制、罰則 | 常に高（専門家確認推奨） |
| 医療 | 健康効果、治療法 | 常に高（薬機法注意） |
| 比較 | 最も〜、唯一〜、1位 | 根拠不明なら高 |
| 因果 | 〜すると〜になる | 断定表現なら中〜高 |

### 自動修正の対象

**自動修正する**:
- 未検証の断定表現 → 推量・伝聞表現に緩和
- 最上級・絶対表現 → 限定的な表現に緩和
- 出典不明の数値 → 「約」「程度」を追加

**手動確認を推奨**:
- 法律・規制関連
- 医療・健康関連
- 企業・製品の固有情報
- 人物の経歴・発言

## 資料作成機能

### 概要

ブリーフ（誰に・何を・どの事実で）から、**16:9のスライド資料**を作ります。
出力は単一のHTMLファイルで、Chromeで開いて `Ctrl/Cmd + P` →「PDFに保存」でそのままスライドPDFになります。

**数値は創作しません。** ブリーフ・参照ファイル・実際に読み取った画面にある数字だけを使い、
実測は🔵観測、こちらの解釈・試算は🟡推定としてスライド脚注で分けて表示します。

### 使い方

#### STEP 1: 案件フォルダを作って、元ネタを放り込む

`projects/_TEMPLATE/` をコピーして `projects/<案件名>/` にします（Claudeに頼んでも作れます）。

```
projects/<案件名>/
├── 00_ブリーフ/deck-brief.md   ← 誰に・何を・どの事実で
├── 01_データ/                  ← ★元ネタをここに放り込む
├── 02_ワーク/                  ← spec.js（Claudeが作る）
└── 03_納品/                    ← 完成したHTML／PDF
```

**`01_データ/` に元ネタのファイルを置くのがいちばん早い使い方です。**
議事録・数値データ・スクリーンショット・PDFなどをそのまま入れてください。

| 形式 | 対応 |
|------|------|
| `.md` `.txt` `.csv` `.tsv` `.json` | そのまま読めます |
| `.png` `.jpg`（スクショ） | そのまま読めます |
| `.pdf` | そのまま読めます |
| `.xlsx` | CSVに書き出して置くのが確実です |

ブリーフ（`00_ブリーフ/deck-brief.md`）は書ける範囲でかまいません。空欄はClaudeが質問します。
特に重要なのは **② この資料のゴール**（読んだ人に何をしてほしいか）です。

**`01_データ/` とブリーフにある数字だけが資料に載ります。** 不足分を推測で埋めることはありません。

#### STEP 2: 資料作成を実行

```
資料作成して
```

宛名を指定する場合：

```
サンプル株式会社様向けの提案資料を作成して
```

#### STEP 3: 構成案を確認する

Claudeがまず**構成案**を出します。ここで内容を確認してください。

1. この資料の主張（1文）
2. 使う事実の一覧（🔵観測 / 🟡推定・出典・取得日つき）
3. 不足している情報
4. スライド構成（表形式）
5. この資料に含めないこと

修正したい点を伝えると構成案を直します。**承認するまでスライドは作られません。**

#### STEP 4: 資料を受け取る

承認後、Claudeが `02_ワーク/spec.js` を書き、ビルドします。

```bash
node engine/build.mjs "projects/<案件名>/02_ワーク/spec.js" "projects/<案件名>/03_納品/<案件名>_<YYYYMMDD>.html"
```

- 出力：`projects/<案件名>/03_納品/<案件名>_<YYYYMMDD>.html`（CSS・JS・データを埋め込んだ1ファイル）
- **PDFにする**：Chromeで開いて `Ctrl/Cmd + P` →「PDFに保存」。用紙サイズ（960×540pt）と余白は設定済みなので、印刷設定は既定のままでかまいません
- **直す**：「5枚目のグラフの数字を直して」と伝えると、spec を直して再ビルドします

### 完成サンプル

`output/sample-deck.html` に、全スライド種別を使った15枚の見本があります。
Chromeで開いて、どんな資料ができるかを確認してください。

### スライドの種類（14種）

| type | 用途 |
|------|------|
| `cover` | 表紙（濃色） |
| `section` | 章扉（濃色） |
| `agenda` | 目次 |
| `facts` | 結論の数字カード（2〜4枚） |
| `kpi` | 指標カード＋読み取り |
| `cards` | 汎用カード（打ち手・メニュー） |
| `table` | 表（5〜7行） |
| `bands` | 全幅の帯（フロー・レイヤー） |
| `compare` | 2カラム比較（できている / できていない） |
| `stats` | 大きい数字（2〜4個） |
| `bullets` | 箇条書き＋補足ボックス |
| `timeline` | ロードマップ（2〜4列） |
| `message` | 濃色1枚メッセージ |
| `cta` | 最終CTA（濃色） |

各スライドのキー・分量の目安は `engine/README.md` を参照してください。

### 色を変える

spec の `theme` で上書きします。`engine/lib/` は共通部品なので編集しません。

```js
theme: {
  primary: "#8541dc",  // メイン色
  accent:  "#f57527",  // アクセント（CTA・警告）
  grad1:   "#2a1655",  // 表紙・章扉のグラデ始点
  grad2:   "#5b2ea8",  // 同 終点
},
```

### 制約

- 出力はHTML／PDFです（pptxは出力しません）
- スライドは自動縮小しません。文字を入れすぎるとカード内であふれるため、`engine/README.md` の分量目安を守ってください
- フォントはNoto Sans JP（オンライン時）。オフラインではヒラギノ・游ゴシック・メイリオにフォールバックします
