# 記事トンマナ＆SEOレビューツール

Claude Codeを使った半自動の記事レビュー＆自動修正システムです。
**ファクトチェック機能**も搭載し、記事の信頼性を高めます。

> 📊 クライアント向けLLMO無料診断レポート（pptx資料）の自動作成については
> [`【公開版】LLMO無料分析/`](【公開版】LLMO無料分析/00_はじめにお読みください.md) を参照してください。
> Claude in Chromeで **「資料作成して」** と話しかけると、このキットのレポート作成フローが起動します
> （詳細は [CLAUDE.md](CLAUDE.md) のタスクルーティングを参照）。

## ディレクトリ構成

```
hibikiclaude/
├── config/
│   └── brand-rules.yaml        # ブランドルール設定（一度設定すればOK）
├── input/
│   └── article.md              # 記事入力用（都度編集）
├── output/
│   └── article-fixed.html      # 修正済みコード出力先
├── templates/
│   ├── review-prompt.md        # レビュー出力形式の定義
│   ├── auto-fix-rules.md       # 自動修正ルール
│   ├── fact-check-prompt.md    # ファクトチェック出力形式
│   └── fact-check-fix-rules.md # ファクトチェック修正ルール
└── README.md
```

## 機能一覧

| コマンド | 機能 |
|----------|------|
| `レビューして` | トンマナ/SEOチェック＆修正案提示 |
| `レビューして修正まで` | レビュー＋自動修正＋HTML出力 |
| `修正だけして` | レビュー省略で修正済みHTML出力 |
| `ファクトチェックして` | 要検証主張の抽出＆チェック計画作成 |
| `ファクトチェックして修正まで` | ファクトチェック＋自動修正＋HTML出力 |

## 使い方

### STEP 1: ブランドルールを設定（初回のみ）

`config/brand-rules.yaml` を開き、以下を設定：

- 口調（ですます/だである）
- トーン（丁寧/カジュアルなど）
- 禁止表現・禁止ワード
- 文字作法（半角全角ルール）
- SEO要件

### STEP 2: 記事と情報を入力（都度）

`input/article.md` を開き、以下を入力：

1. **記事情報**（表形式）
   - 目的
   - ターゲットKW
   - 二次KW
   - 競合差分

2. **記事本文**
   - コードブロック内に貼り付け

### STEP 3: レビュー＆修正を実行

#### レビューのみ
```
レビューして
```

#### レビュー＋自動修正＋HTML出力（推奨）
```
レビューして修正まで
```

### STEP 4: 結果を受け取る

**レビュー結果**:
1. 総評（200字以内）
2. トンマナ逸脱リスト（表形式）
3. 読みやすさ改善（箇条書き）
4. SEO改善（箇条書き）
5. 重要度タグ（A/B/C）
6. 修正後サンプル文章（3箇所）

**修正済みHTML**:
- `output/article-fixed.html` に出力
- 修正ログも併せて表示

## 自動修正の対象

### 重要度A（必須修正）- 自動対応
| 項目 | 内容 |
|------|------|
| カギ括弧削除 | 「」を全て削除 |
| 問いかけ修正 | 〜ませんか？→平叙文に変換 |
| HTML構文修正 | 閉じタグ漏れ等を修正 |

### 重要度B（推奨）- 自動対応
| 項目 | 内容 |
|------|------|
| 長文分割 | 80字超の文を分割検討 |
| 表記統一 | brand-rules.yaml に従い統一 |

### 手動対応が必要
- SEO関連（タイトル、KW配置）
- コンテンツの追加・削除
- 画像alt属性の設定

## カスタマイズ

### 禁止ワードを追加する

`config/brand-rules.yaml` の `prohibited.words` に追加：

```yaml
prohibited:
  words:
    - "絶対"
    - "必ず"
    - "誰でも簡単に"
```

### 用語統一を設定する

`config/brand-rules.yaml` の `writing_rules.terms` に追加：

```yaml
writing_rules:
  terms:
    SEO: "seo, Seo"
    Webサイト: "WEBサイト, webサイト"
```

## ファクトチェック機能

### 概要

記事内の「検証が必要な主張」を自動抽出し、チェック計画を作成します。
数値、統計、法律、医療など、誤りがあると信頼性を損なう情報を重点的にチェックします。

### 使い方

#### STEP 1: 記事を入力
`input/article.md` に記事本文を貼り付け

#### STEP 2: ファクトチェック実行
```
ファクトチェックして
```

#### STEP 3: 結果を確認

**出力内容**:
1. リスク評価の総評（100〜200字）
2. 要検証リスト（表形式）
3. 断定回避テンプレ（5つ）
4. 最優先確認リスト（上位5件）

#### STEP 4: 修正まで実行（オプション）
```
ファクトチェックして修正まで
```

### ファクトチェック出力サンプル

```
## 1) リスク評価の総評
本記事には12件の検証が必要な主張が含まれています。
特に数値データ（5件）と法律関連（2件）はリスクが高く、
公式出典での確認が必須です。医療効果に関する記述は
表現の緩和を推奨します。

## 2) 要検証リスト
| # | 主張 | 種類 | リスク | 理由 | 検証方針 | 推奨出典 | 修正案 |
|---|------|------|--------|------|---------|---------|--------|
| 1 | 利用者数は1億人を突破 | 数値 | 高 | 出典不明 | 公式発表を確認 | 企業IR/プレスリリース | 約1億人以上とされています |
| 2 | 業界シェア1位 | 統計 | 高 | 比較時点不明 | 調査会社データを確認 | 矢野経済研究所等 | 主要なサービスの一つ |

## 3) 断定回避テンプレ
- 〜とされています
- 〜と言われています
- 〜という報告があります
- 一般的に〜と考えられています
- 〜の傾向が見られます

## 4) 最優先確認リスト
1. 利用者数は1億人を突破（数値/高）- 法的リスク回避のため
2. 業界シェア1位（統計/高）- 景表法違反リスク
3. ...
```

### チェック対象の種類

| 種類 | 説明 | リスク基準 |
|------|------|-----------|
| 数値 | 具体的な数字、金額、% | 出典不明なら高 |
| 統計 | 調査結果、ランキング | 時点・母数不明なら高 |
| 法律 | 法令、規制、罰則 | 常に高（専門家確認推奨） |
| 医療 | 健康効果、治療法 | 常に高（薬機法注意） |
| 比較 | 最も〜、唯一〜、1位 | 根拠不明なら高 |
| 因果 | 〜すると〜になる | 断定表現なら中〜高 |

### 自動修正の対象

**自動修正する**:
- 未検証の断定表現 → 推量・伝聞表現に緩和
- 最上級・絶対表現 → 限定的な表現に緩和
- 出典不明の数値 → 「約」「程度」を追加

**手動確認を推奨**:
- 法律・規制関連
- 医療・健康関連
- 企業・製品の固有情報
- 人物の経歴・発言
