# LLMO無料分析 — アウトプットフェーズ（llmo-free-report）

Emma LLMOツールの実測データから、クライアント向け無料分析レポート（pptx・約26枚）を対話ベースで作る。

## 0. 前提・鉄則
- **数値（KPI・順位・掲載状況・スコア）はツールの実測（🔵）のみ**。無い数値を創作しない。
- **ヒアリング差分・所見・方向性は 🟡（推定・提言）**としてラベル分離する。
- **無料版のスコープを守る**：
  - 計測プロンプトは限定本数（レポートにもその旨を明記）
  - サイテーションのメディアリストは**サンプル3〜4行のみ**。全リストは出さない（有償）
  - 対策は**方向性のみ**。タスク分解・実行手順を書くとコンサルティング領域になるので書かない
- **06章の後ろに「対応範囲」「料金の考え方とサンプル料金」の2枚が自動で入る**（エンジンの固定パート）。specには通常なにも書かない。
  内容と出典・注意点は [references/ツール・モニタリング料金と対応範囲.md](../references/ツール・モニタリング料金と対応範囲.md)。
  **料金は営業資料の「仮案」由来で【提案】項目を含むため、クライアント提示前に最新の確定条件を確認すること。**
- 登録フェーズ（llmo-registration）が完了し、ツールに計測データが入っていることが前提。無ければ先に登録フェーズへ。

## STEP 1｜クライアントとサイトの選択（選択確認は必須）
1. メンバーに「クライアント名」と「対象サイト」を確認する。
2. `03_クライアントレポート/<クライアント名>/` が無ければ `_新規クライアント_TEMPLATE` をコピーして作る。
3. `00_ヒアリング/` のヒアリングシートを読み込む（ブランド定義の「ありたい認識」が差分分析に必須）。
4. Claude in Chrome でツールを開き、**左上ヘッダの2つのプルダウン（クライアント／サイト）を読み取り、対象と一致しているか必ず確認する**。
   - 一致していなければ切り替え、**切り替え後にもう一度読み取って一致を確認**してから先に進む（前回作業したクライアントが残っていることがある）。
   - **この確認が取れるまで、いかなるデータも読み取らない・記録しない。**
   - 以降も**ページを遷移するたびに**ヘッダのクライアント名を確認する（読み取りデータの取り違え防止）。確認結果は `02_ワーク/データ取得メモ.md` に「選択確認：<クライアント>/<サイト>」として残す。

## STEP 1.5｜計測データの存在チェック（無ければここで停止）
レポートに使う計測データは、**セッション開始前にツール内で作成しておく運用**（計測実行はレポート作成時にはやらない）。
`/monitoring` を開き、以下をチェックする：
- 「最終取得」日時が存在するか
- ジャーニー4KPI（引用率/言及率/勝率/ポジ率）に数値が入っているか
- プロンプト一覧が「未計測」ばかりでないか

**1つでも満たさない場合は、ここで作業を停止する。** spec作成・pptx生成に進んではいけない（数値の穴を推定で埋めることは絶対にしない）。
メンバーには次を案内して終了する：
> 「このクライアントはまだ計測データがありません。ツールの /monitoring で『計測を実行』し、完了後（通常しばらく時間がかかります）に改めて『レポート作って』と依頼してください。登録がまだの場合は先に登録フェーズ（llmo-registration）を行います。」

また、最終取得日が**30日以上前**の場合は停止はしないが、「データが古い（<日付>取得）。再計測してから作ることを推奨」とメンバーに確認を取ってから進める。

## STEP 2｜データ取得（4分析ページ）
取得方法は3経路。**上から順に試す**（詳細：[01_マニュアル/04_データ取得マニュアル.md](../../01_マニュアル/04_データ取得マニュアル.md)）。

- **A. Claude in Chrome（第一選択）**：各ページを開いて読み取る。1タブを使い回し、終了時に閉じる。
- **B. 貼り付けファイル**：`01_データ/` にメンバーが置いたスクショ（PNG）または Gemini in Chrome で書き出したテキスト（[templates/Gemini用データ抽出プロンプト.md](../templates/Gemini用データ抽出プロンプト.md) を使用）を読む。**ファイルが既に置かれている場合はBを優先**。
- どちらも無理なら、必要なページと取得手順をメンバーに具体的に案内して待つ。

取得する4ページと読み取り項目：

| ページ | 読み取ること | 参照 |
|---|---|---|
| `/monitoring` | ジャーニー4段階のKPI（情報収集=引用率／ブランド想起=言及率・平均順位／比較検討=勝率／意思決定=ポジ率）、強い・弱いプロンプト群、計測日 | [references/ファネルKPIの読み方.md](../references/ファネルKPIの読み方.md) |
| `/brand-listening` | ポジション方針の達成状況（意図どおり/要対策）、自社が勝者の認識軸、競合支配・圏外の認識軸 | [references/ブランド差分分析.md](../references/ブランド差分分析.md) |
| `/citation-list` | 掲載数/全媒体数、平均掲載順位、掲載依頼候補数、Impact Score上位の未掲載メディア3〜4件（媒体名・記事名・AI引用回数・競合掲載状況） | [references/サイテーション分析.md](../references/サイテーション分析.md) |
| `/site-audit` | 平均スコア、診断ページ数、S/A/B/C分布、低スコアページの傾向 | [references/サイト診断要約.md](../references/サイト診断要約.md) |

取得した生データは `02_ワーク/データ取得メモ.md` に取得日時つきで保存する（後から検証できるように）。

## STEP 3｜分析（🟡はここから）
1. **ファネル分析**：4KPIのどこで落ちているか、原因仮説（プロンプト群の傾向から）
2. **ブランド差分分析**：ヒアリングの「ありたい認識」×ツールの「現状認識」→ 強めるべき軸・作るべき軸・抑えるべき軸
3. **サイテーションギャップ**：掲載可能性の総数を示し、象徴的なサンプル（競合掲載あり×自社なし／自社が下位掲載）を3〜4件選ぶ
4. **サイト要因**：スコア分布とファネル弱点の関係（例：意思決定が弱い×信頼系ページが低スコア）
5. **FACT3つ**：強み1・課題1・機会1 を実測値つきで
6. **対策の方向性4つ**：実測に紐づけて。**タスク分解しない**

分析結果を対話でメンバーに提示し、フィードバックを反映してから次へ。

## STEP 4｜spec作成 → pptxビルド
1. `04_共通素材/エンジン/specs/_TEMPLATE/` をコピーして `specs/<クライアント名>/spec.js` を作成し、STEP2/3の内容で埋める（スキーマ：`specs/README.md`、完成例：`specs/サンプル_EmmaTools/spec.js`）。
2. ビルド：
   ```
   cd 04_共通素材/エンジン
   node build.js "specs/<クライアント名>/spec.js" "../../03_クライアントレポート/<クライアント名>/03_納品/<クライアント名>_LLMO無料分析_<YYYYMMDD>.pptx"
   ```
3. 生成したpptxをメンバーに渡して確認してもらう。修正は spec を直して再ビルド。
4. specのコピーを `02_ワーク/` にも置く（納品版の再現用）。

## STEP 5｜サマリーと引き継ぎ
- [templates/分析サマリー_テンプレート.md](../templates/分析サマリー_テンプレート.md) の体裁で `03_納品/分析サマリー_<YYYYMMDD>.md` を作成（観測🔵/推定🟡ラベル付き）。
- 出力前チェックリスト：
  - [ ] 数値はすべてツール実測。創作なし・計測日明記
  - [ ] 🔵/🟡がスライド脚注で分離されている
  - [ ] メディアリストはサンプルのみ（全リストを載せていない）
  - [ ] 対策は方向性のみ（タスク・手順を書いていない）
  - [ ] ご支援メニュー（コンサル月60万円〜／ツール契約／レポーティング＋助言 月1回）とブランド定義見直し支援（CEP分析・n1分析・カテゴリコンセプト開発）が入っている
  - [ ] 料金2枚（対応範囲・サンプル料金）の数字が最新の確定条件と一致している（[references/ツール・モニタリング料金と対応範囲.md](../references/ツール・モニタリング料金と対応範囲.md)）
  - [ ] 納品物が `03_クライアントレポート/<クライアント名>/03_納品/` に揃っている
